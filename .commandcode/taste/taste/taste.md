# Taste
- Treats the project's spec/design docs (`design.md`, `FUNCTIONALITY.md`) as authoritative: every documented functionality must be implemented and the stated design language followed closely rather than improvised. Confidence: 0.9
- Expects existing features to be preserved when new ones are added; a doc rule never justifies deleting functionality he did not ask to remove. Reacts strongly (in caps) when shipped features — news, watchlist, reader, events, AI summary — disappear during a redesign. Confidence: 0.95
- Wants deep configurability: a settings surface with many appearance options (theme tone, metal finish, grain, accent, shape, density, motion) *and* functional options, with "everything" tweakable, reachable from a Settings tab in the nav rather than a "More" menu. Confidence: 0.9
- Prefers very dark interfaces, as dark as possible while remaining legible/on-theme, and explicitly wants an AMOLED (true-black) mode rather than a single fixed dark theme. Confidence: 0.85
- When a new design language is introduced, prefers a complete whole-app redesign over piecemeal adaptation. Confidence: 0.7
- Cares strongly about UI polish and motion: wants a good number of "lovely" UX animations and a very polished, minimal-bug experience. Confidence: 0.85
- Demands rigorous verification of shipped features ("tested vigorously", "minimal bugs") — expects documented functionality to be exercised with tests, not just implemented. Confidence: 0.85
- Does not rely on a physical phone for testing; an emulator is acceptable when needed. Confidence: 0.7
- Keeps projects and scratch work under `/mnt/shared` and avoids installing heavy applications into the system root; prefer confined, non-system-wide installs. Confidence: 0.85
- Prefers generous, legible typography on mobile: flags small text as a defect ("font size is too small") and expects the base type scale to be raised rather than patched per screen, with no tiny micro-labels. Confidence: 0.85
- Prioritizes scroll smoothness as a first-class requirement; treats list/scroll lag as a bug to be profiled and fixed (draw-call count, per-frame allocations, per-row O(n) work) rather than tolerated. Confidence: 0.85
- Prefers minimal copy in the UI: strip redundant labels, prefixes, units and explanatory captions ("too much text is bad"), while keeping the remaining text readable and the hierarchy intact. Confidence: 0.85
- Prefers visual restraint over repetition: expressive surface treatments (metal, glows) should be reserved for a few important containers (nav bar, hero, primary actions) and everything else kept flat; a screen full of identical heavy containers is a defect. Confidence: 0.85
- Expects decorative effects to respect container geometry — an ambient glow/edge light must be clipped to the shape and follow the rounded corners on all four sides rather than bleeding past them or lighting only the top. Confidence: 0.75
- Expects appearance settings to apply consistently to *every* surface, including app chrome like the floating nav bar — no component exempt from the user's chosen finish. Confidence: 0.75
- When he asks for a feature to be removed, he means removed completely — not hidden behind a settings toggle or a config flag. Confidence: 0.8
- Likes gesture-based navigation: swipe left/right to move between the main tabs, with the transition direction matching the gesture. Confidence: 0.7
- Prefers smart defaults that avoid blank first screens — e.g. opening on a populated view (Markets) when the primary list (watchlist) is empty. Confidence: 0.65
